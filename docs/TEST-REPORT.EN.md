the taxonomy table had been typed by hand and mislabelled `GCF_000008105.1` as

## 5. What was measured

### 5.1 Marker-selection knobs actually decide something

| Knob | Differential measurement | Artefact field |
|---|---|---|
| `--max-markers 2 / 4 / 8` | "Markers selected" = 2 / 4 / 8 | `v07_budget.selected_per_ceiling` |
| `--min-occupancy 0.50 / 0.95` | 20 markers kept → 17 kept | `v07_occupancy` |
| `--marker-preset …` | each named preset overrides the explicit budget; `none` leaves it | `v07_preset_*` |
| `--mode conservative/standard/expanded/mag_adaptive` | each completes and labels itself in the summary | `v07_mode_*` |
| `--min-marker-coverage` (deprecated) | selects the same 8 markers as `--min-occupancy` and says it is an alias | `v07_alias` |

`--max-markers` was previously read, recorded, then overridden by the Phase-0
adaptive budget: the knob existed and did nothing. It is now applied after
adaptation (and so is an explicit `--marker-preset`), which is what the first
row measures.

### 5.2 The phylogenetic HGT screen separates concordance from conflict

Measured on the 8-genome set at `--monophyly-rank order`, where two taxa are
testable per marker:

| Quantity | Value | Where |
|---|---|---|
| Taxa tested per marker (`n_total`) at order rank | 2 | `hgt_evaluation.tsv` |
| Monophyly proportion distribution | 0.0 and 0.5 among the 4 scored markers | `hgt_evaluation.tsv` |
| `--monophyly-threshold 0.0` vs `1.0` | 3 markers flagged vs 3 flagged (floor at 0 flags nothing extra; at 1 nothing survives) | `v04_monophyly` |
| `--hgt-threshold-l2l3 0.9` vs `0.1` | 0 excluded → 2 excluded | `v06_l2l3` |
| `--hgt-threshold` (deprecated alias of L1/L2) | Level-1 count 4 → 2, Level-3 count unchanged | `v06_alias` |
| `--hgt-adaptive-thresholds` | `level2_max` 0.6 → 0.95, announced as far-distance; default run says nothing | `v06_adaptive` |
| Ranking-only demotion (consistency criterion) | `--cog-category-map` fills `functional_category` on profiled markers; without it the column reads `NA` with a note | `v06_cog` |

Three behaviours of this screen were wrong and are fixed, because the validation
data exposed them: the monophyly verdict depended on where MAD put the root (the
manual states it is root-invariant; the code tested rooted-clade membership
only); a taxon whose complement is a single tip was counted as a measurement
(7-vs-1 sampling cannot falsify anything, and the code turned that into risk
1.0 for perfectly concordant trees); and `--monophyly-rank`, documented as the
rank to measure at, was overridden by a scope-derived rank the user could not
turn off. Default is now `auto` (derive from the tree); naming a rank means it.

### 5.3 Gates, assertions and exit codes

| Mechanism | Measured outcome | Exit code |
|---|---|---|
| 14 registered output assertions on a healthy run | 14 PASS / 0 WARN / 0 FAIL | 0 |
| `--taxonomy-mustpass` satisfied | `groups_tested=8; markers_checked=8` — a gate that tested something | 0 |
| `--taxonomy-mustpass` violated (split-genus twin table) | run aborts, violation named | 4 (`EXIT_ASSERTION_FAILED`) |
| `--taxonomy-mustpass` pointing at a missing baseline | refuses rather than passing | 4 |
| `--allow-assertion-failure` bypass | bypass is recorded in the products | 4 → run completes with the bypass flagged |
| Recommendation inconclusive | documented exit 5 reachable and labelled | 5 |
| Argument errors (`-t 0`, `--min-occupancy 1.5`, `-o` onto a file) | refused with a message, no traceback | 2 |

The must-pass gate used to read the *path* of the gene-tree cache file as if it
were Newick, so it tested zero relations and printed "all required relations
hold". The artefact-backed assertion above is what keeps that shape of failure
from returning.

### 5.4 Inference and products

* `--gene-tree-builder fasttree` and `iqtree` both complete; support values are
  present only where the builder produces them, and the label says which
  (`v09_support`, `v09_builder`).
* `--coalescent-mode off / post-filter / always` → the ASTRAL tree is absent,
  present, present respectively (`v09_coalescent_*`), and the recommendation
  text follows the trees that exist.
* All 18+1 product kinds are opened and parsed: TSV headers, decision-card JSON
  schema, Nexus partition (`charsets` = markers kept by the screen, which is not
  the Phase-1 selected count), HTML report, run_config, step state
  (`v14_products`, `v14_partition`, `v14_cards`, `v13_*`).
* Species-tree tip sets are read after stripping FastTree's support labels, so a
  label like `72` is not counted as a taxon (`v14_trees`).
* Nothing is written outside the output directory; per-run scratch is isolated
  between concurrent runs (`v13_tmp`, `v13_tmp_isolation`, `v13_intermediates`).

### 5.5 Reproducibility, determinism, replay

| Claim | Measurement |
|---|---|
| Same input twice → same scientific content | 44 comparable files, **0 differing** after normalising timestamps, run duration and per-run paths (`v15_determinism`) |
| Marker ranking is run-order independent | identical ranking over two runs (`v15_ranking`) |
| A recorded `run_config.json` replays | differing parameters: **[]** (`v02_replay`) |
| A replayed run reproduces the products | same marker set as the recorded run (`v15_replay`) |
| Caches state what they were built from | 19 cached gene trees, 19 input stamps; a rerun reuses rather than rebuilds (`v14_tree_cache`) |
| Seeds are pinned, not left to the clock | gene-tree and support values identical across runs (`v15_seeds`, `v09_ufboot`) |

Two of these are new. Replaying a snapshot used to be a no-op wearing the name:
`run_config.json` nests its parameters per module and renames a few fields, so
the loader dropped the marker directory, the taxonomy table and the risk bands as
"unrecognized keys"; paths were stored relative to the output directory but read
relative to the current directory, so a replay reached into `../../../tmp/…`.
And the per-marker gene-tree cache was keyed by marker id alone, which let a tree
inferred from *different* sequences answer the next run's request. Snapshots are
now recorded with resolved paths, flattened back onto the command-line vocabulary
on read, with the *requested* budget restored rather than the adapted one, and
gene-tree cache entries carry the SHA-256 of the sequences they were built from.

### 5.6 Robustness: refusal must be specific and loud

Degenerate inputs are exercised, not dodged: 2-tip and 1-tip marker files, a
3-genome set (below the 4-tip minimum for a gene tree), a marker directory of
unusable profiles, an empty `.faa`, a non-FASTA file, a taxonomy table whose
header row would otherwise become a phantom tip, an illegal reference tree, a
missing HMM directory. Each case requires a non-zero exit, a message naming the
offending path, no traceback, and no empty placeholder product
(`v16_degenerate.exit_code = 3`, `v16_three_tips.exit_code = 3`).

The generic refusal text used to claim "all markers were flagged as Level 3" even
when Phase 1 had selected nothing; it now distinguishes the two, because the
advice for one is wrong for the other.

### 5.7 Detection against planted positives (the 12-genome benchmark)

The paired design: 20 markers over 12 genomes, and the same directory with 3
cross-order transfers planted. Both runs are executed by the suite; the numbers
below are read off the products, not asserted a priori
(`validation/results/chimera_metrics.json`).

| Quantity | Value |
|---|---|
| Markers scored in both runs | 20 |
| Planted markers excluded (risk = 1.0) in the chimeric run | **3 / 3** |
| Planted markers whose risk *rose* against the clean run | 2 |
| Planted marker already at maximum risk in the clean run | 1 (`TIGR00061`) — a measured false positive, recorded as such |
| Unplanted markers whose risk moved between the paired runs | 0 |
| Background exclusion rate on clean data | 0.1 |
| Precision / recall / F1 at the exclusion decision | 1.0 / 0.667 / 0.8 |

The distinction matters: a planted positive that the clean run already flags
cannot "rise", so demanding a rise from all three would either be unsatisfiable
or would force the baseline error rate out of sight. The case therefore asserts
that every planted marker is excluded, that the bystanders are silent, and that
the baseline is not saturated — and it publishes the baseline number. `xfail`
is reserved for what the suite knows it cannot yet claim; nothing in this run
depends on an expected failure to look green.

## 7. What this validation does **not** establish

* **GTDB-Tk equivalence.** The marker inputs reconstruct GTDB-Tk's *layout*
  (one FASTA per marker, unaligned sequences, filename = marker id) from
  hmmsearch over those fetched profiles; GTDB-Tk's own taxonomy-aware best-hit
  selection is not reproduced. The numbers above measure MarkerFinder's decisions
  on a layout-faithful input, not GTDB-Tk's marker choice.
* **Epidemiological detection rates.** 3 planted cross-order transfers over 12
  genomes, with a measured background rate, is a positive control with known
  answers — not a sample of real HGT. Larger estimates come from
  `tests/benchmark/` (30 genomes, GTDB r53 truth), user-triggered because of its
  download size.
* **COG biology.** The functional-category column is filled from the fetched
  profiles' own annotation lines, so it exercises the `--cog-category-map` path.
* **Occupancy extremes.** The fetched profile set is a conserved-marker set, so the
  sparsest natural marker over these related genomes still sits at occupancy
  0.875; sparser inputs had to be truncated (2-tip / 1-tip) and are labelled as
  such in `validation/data/markers/degenerate/README`.
* **Python 3.13 and newer.** ete3 imports the stdlib `cgi` module at
  package-import time and CPython removed `cgi` in 3.13 (PEP 594), which used to
  make ete3 — and every MAD / monophyly measurement — unusable on newer
  interpreters. `markerfinder._cgi_compat` now installs a minimal `cgi`
  stand-in when, and only when, the real module is absent, so 3.13 and 3.14 are
  inside the supported range and the CI matrix runs them. The absence of an
  upper bound is itself under test rather than asserted in prose. Residual risk:
  the shim covers only the one symbol ete3 touches (`cgi.FieldStorage`) and raises
  `NotImplementedError` if anything actually calls it. MarkerFinder never uses
  the ete3 web plugin, so that path is not exercised.
* **A writable `/tmp`.** MAFFT creates scratch with `mktemp -dt` and, when that
  fails, continues with an empty path and produces no alignment — which the
  pipeline then reported as "no markers could be aligned". The suite pins
  `TMPDIR`/`MAFFT_TMPDIR` inside `validation/.work` so a container with a
  read-only `/tmp` cannot turn into a wrong scientific verdict.

## 8. How to reproduce this report

```bash
conda env create -f environment.yml && conda activate markerfinder
# The HMM profiles are third-party work and are not committed:
python scripts/fetch_marker_db.py --auto
# optional: rebuild the shipped data from NCBI (network)
python validation/run_validation.py --prepare
# the acceptance layer, including the slow detection benchmark
python validation/run_validation.py --all -n 8
# the fast layer, whose numbers this report also quotes
pytest tests
```

`run_validation.py` writes `validation/results/{junit.xml,metrics.json,
capability_matrix.tsv,environment.txt}`; the report quotes those files, and the
consistency test re-reads them.
