Identifier-scheme variant of the quad4 set: the same four genomes and the same sequences, renamed mag_01..mag_04 so that MarkerFinder's filename-based MAG classification fires. Generated by scripts/03_build_fixtures.py; nothing here is a different measurement.
rename map: {'GCF_000009045.1': 'mag_01', 'GCF_000007825.1': 'mag_02', 'GCF_000009645.1': 'mag_03', 'GCF_000196035.1': 'mag_04'}

genomes/mag_01.faa .. mag_04.faa are SYMLINKS into ../../genomes/GCF_*.faa. They are
committed as links, not as copies, because those proteomes are third-party NCBI
data that this repository does not redistribute. Two consequences:

  * In a fresh checkout the four links are DANGLING, because
    validation/data/genomes/ is gitignored. Run the acceptance layer through
    `python validation/run_validation.py --prepare`, which fetches the
    proteomes and has 03_build_fixtures.py unlink and recreate each link.
  * On Windows, git checks these out as regular files whose content is the
    target path (36 bytes of text, not FASTA). --prepare replaces them with
    real links; creating a symlink there needs Developer Mode or an elevated
    shell, and fails loudly with OSError rather than corrupting the data.
